# Getting Started

## Compatibility Overview

This SDK supports both the React Native new and old architecture. There is one known Android limitation: embedded Lucra views use Jetpack Compose, which is not supported by `react-native-screens`. If you need embedded components on Android, stay on the old architecture for now.

Minimum platform requirements:

- iOS deployment target: 15.1
- Xcode 26.6 or newer. The Lucra iOS SDK 7.0.1 binary is built with Xcode 26.6 (Swift 6.3.3) and is also verified under Xcode 27.0; earlier Xcode 26.x toolchains have not been verified against its Swift module interface. Any future change to the Xcode floor is called out as a breaking change in the [release notes](SDK_RELEASE_NOTES.md). Building with Xcode 27 needs the extra CocoaPods step in [Xcode 27 and CocoaPods Resource Bundles](#xcode-27-and-cocoapods-resource-bundles).
- Android minSdk: 24

Each wrapper release pins exact native SDK versions (`LucraSDK` on CocoaPods, `com.lucrasports.sdk:sdk-core` and `sdk-ui` on Maven Central). The pins, and any change to the native SDKs' third-party dependencies, are listed per version in the [release notes](SDK_RELEASE_NOTES.md).

## Private Package Access (Required)

You need a Personal Access Token (PAT) to:
- Install the NPM package from GitHub Packages
- Access the private iOS CocoaPods repository

**Note:** Android SDK artifacts are published to Maven Central and do not require authentication.

1. Create a PAT: https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens
2. Select "Classic" with the `read:packages` scope (add `repo` only if you also need private-repository access)
3. Name it something like `Lucra Token`
4. Use it when prompted during install or in CI

## NPM Install

Create a `.npmrc` at the root of your app:

```
//npm.pkg.github.com/:_authToken=[INSERT YOUR GITHUB PERSONAL TOKEN HERE]
@lucra-sports:registry=https://npm.pkg.github.com
```

You can also set it as an environment variable and then use variable replacement. In this example under `GITHUB_PERSONAL_TOKEN`:

```
//npm.pkg.github.com/:_authToken=${GITHUB_PERSONAL_TOKEN}
@lucra-sports:registry=https://npm.pkg.github.com
```

Install the package:

```sh
npm i -S @lucra-sports/lucra-react-native-sdk react-native-haptic-feedback react-native-webview
```

Do not commit `.npmrc` to your repo. Add it to `.gitignore`.

## Expo (Prebuild/Ejected Only)

This SDK does not work with Expo Go. You must use `expo prebuild`, a dev client, or a standalone build.

### Using Expo Build Properties

Install `expo-build-properties` dependency, then update `app.config.js` to set native build properties and register the Lucra plugin:

```javascript
plugins: [
  [
    'expo-build-properties',
    {
      ios: {
        // Apply only if you are using a old expo version
        deploymentTarget: '15.1',
        // Lucra SDK uses third-party services that require network inspection to be kept off.
        networkInspector: false,
      },
      android: {
        minSdkVersion: 24,
        networkInspector: false,
      },
    },
  ],
  '@lucra-sports/lucra-react-native-sdk',
],
```

The plugin forces static frameworks (`ios.useFrameworks = static`) and, during `expo prebuild`, adds the Podfile `pre_install` hook from [Sentry Framework Linkage](#sentry-framework-linkage) that builds only the Sentry pod as a dynamic framework. Without that hook a static-framework build dies at launch, so no manual Podfile edit is needed.

### Custom Fonts

Follow the `expo-font` guide and ensure Lucra can resolve your font family:

- Android: pass paths relative to `fonts/`.
- iOS: pass the font family name (as shown in Font Book).
- Provide all variations: Regular, Medium, SemiBold, Bold.

### Expo Dev Client

If you use `expo-dev-client`, make sure `networkInspector` is `false`. The SDK uses libraries that block network inspection.

### Venmo Deeplinks (Expo)

Add iOS Info.plist entries for Venmo:

```javascript
infoPlist: {
  CFBundleURLTypes: [
    {
      CFBundleURLSchemes: ['YOUR_APP_BUNDLE_IDENTIFIER.venmo'],
      CFBundleURLName: 'Venmo URL Scheme',
    },
  ],
  LSApplicationQueriesSchemes: ['venmo', 'com.venmo.touch.v2'],
},
```

## iOS Setup

### Deployment Target

If you are using an older React Native/Expo version, you need to set the minimum iOS version to 15.1:

```ruby
platform :ios, 15.1
```

Newer React-Native/Expo versions should already target iOS 16.1, so you might not need this.

### CocoaPods Sources

In your `ios/Podfile`, add Lucra's private repo and CocoaPods source at the top:

```ruby
source 'https://github.com/Lucra-Sports/lucra-ios-sdk.git'
source 'https://cdn.cocoapods.org/'

use_frameworks! linkage: :static
```
### Xcode 27 and CocoaPods Resource Bundles

Xcode 27 (optional for wrapper 7.0.0, see [Compatibility Overview](#compatibility-overview)) refuses to build any target whose deployment target is below iOS 15.0. `react_native_post_install` raises the deployment target on pod targets but not on the resource-bundle targets CocoaPods generates alongside them (`*_Privacy`, `*_resources`), which keep whatever their podspec declared — 9.0 for PromisesObjC, 11.0 for Sentry, 12.x–13.4 for the Firebase, Google and AsyncStorage pods. If your build fails with `The iOS Simulator deployment target 'IPHONEOS_DEPLOYMENT_TARGET' is set to 12.0, but the range of supported deployment target versions is 15.0 to 27.0.x`, add this to your `post_install` hook after `react_native_post_install`:

```ruby
installer.target_installation_results.pod_target_installation_results.each do |_, result|
  result.resource_bundle_targets.each do |bundle_target|
    bundle_target.build_configurations.each do |config|
      config.build_settings['IPHONEOS_DEPLOYMENT_TARGET'] = min_ios_version_supported
    end
  end
end
```

### Sentry Framework Linkage

The Lucra iOS SDK depends on `sentry-cocoa` for its own internal diagnostics and links its **dynamic** product. It never calls `SentrySDK.start` and sends nothing to your Sentry project, but the dynamic `Sentry.framework` must be embedded in your app. The wrapper's podspec declares the `Sentry` pod as `~> 8.58` (8.58.0 or newer within 8.x), the same constraint as the native `LucraSDK` podspec; Lucra iOS SDK 7.0.1 is built against sentry-cocoa 8.58.4 and verified against 8.58.0, the version `@sentry/react-native` 7.11.0 pins through `Sentry/HybridSDK`. What you control is how it is linked.

With `use_frameworks! linkage: :static`, the Sentry pod builds as a static framework and the app dies at launch with `dyld: Library not loaded: @rpath/Sentry.framework/Sentry`. Either use dynamic linkage (`use_frameworks!`) or keep static linkage and build only Sentry dynamically:

```ruby
# ios/Podfile, after `use_frameworks! linkage: :static`
pre_install do |installer|
  installer.pod_targets.each do |pod|
    next unless pod.name == 'Sentry'
    def pod.build_type
      Pod::BuildType.dynamic_framework
    end
  end
end
```

The hook changes only the `Sentry` pod: it becomes one dynamic framework shared by Lucra's diagnostics and your own Sentry, and every other pod keeps static linkage. Expo projects get the hook from the config plugin.

If your app also uses Sentry (for example `@sentry/react-native`), align it to `sentry-cocoa` 8.58.0 or newer within 8.x. sentry-cocoa 9.x is not supported: the native SDK binary links the 8.x framework and the `LucraSDK` podspec caps the dependency below 9.0, so an older pin or a 9.x pin fails dependency resolution with `could not find compatible versions for pod "Sentry"`.

### Add Lucra Private Pod Repo

```sh
pod repo add LucraSDK https://github.com/Lucra-Sports/lucra-ios-sdk
# OR
pod repo add LucraSDK git@github.com/Lucra-Sports/lucra-ios-sdk
```

```yml
- name: Add private repo to cocoapods
```

## Android Setup

### Maven Repository Setup

Lucra Android Native SDK artifacts are published to Maven Central. No additional authentication is required.

Ensure your root `android/build.gradle` includes Maven Central:

```gradle
allprojects {
  repositories {
    google()
    mavenCentral()
  }
}
```

### Sentry Version Alignment (If Your App Uses Sentry)

The Lucra Android SDK depends on `io.sentry:sentry` 8.54.0 for its own internal diagnostics. It never calls `Sentry.init` and sends nothing to your Sentry project. If your app also uses Sentry, every `io.sentry:*` artifact must resolve to the same version, 8.54.0 or newer. Gradle only raises the artifacts both sides share, so `@sentry/react-native` (7.11.0 brings `sentry-android` 8.31.0) leaves `sentry-android-core` at 8.31.0 next to `sentry` 8.54.0, and the app dies at process start, before `Sentry.init`, with `NoClassDefFoundError: io.sentry.util.runtime.IRuntimeManager` in `installContentProviders`; other mixes surface as `Sentry SDK has detected a mix of versions` or `AbstractMethodError`. Pin the group in `android/app/build.gradle` (`sentry-native-ndk` is versioned separately and must be left alone):

```gradle
configurations.all {
  resolutionStrategy.eachDependency { details ->
    if (details.requested.group == 'io.sentry' && details.requested.name != 'sentry-native-ndk') {
      details.useVersion '8.54.0'
    }
  }
}
```

The example app carries this block and runs `@sentry/react-native` 7.11.0 against it.

### Application Requirements

Lucra uses [Coil](https://coil-kt.github.io/coil/) for images and SVGs. Provide the Lucra image loader in your `Application`:

```kotlin
class MyApplication : Application(), ImageLoaderFactory {
  override fun newImageLoader() = LucraCoilImageLoader.get(this)
}
```
