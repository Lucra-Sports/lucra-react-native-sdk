# Getting Started

## Compatibility Overview

This SDK supports both the React Native new and old architecture. There is one known Android limitation: embedded Lucra views use Jetpack Compose, which is not supported by `react-native-screens`. If you need embedded components on Android, stay on the old architecture for now.

Minimum platform requirements:

- iOS deployment target: 15.1
- Android minSdk: 24

Each wrapper release pins exact native SDK versions (the Lucra iOS SDK frameworks that `pod install` downloads, see [Lucra iOS SDK Frameworks](#lucra-ios-sdk-frameworks), and `com.lucrasports.sdk:sdk-core` and `sdk-ui` on Maven Central). The pins, and any change to the native SDKs' third-party dependencies, are listed per version in the [release notes](SDK_RELEASE_NOTES.md).

## Private Package Access (Required)

You need a Personal Access Token (PAT) to install the NPM package from GitHub Packages.

**Note:** Native SDK artifacts do not require authentication: the iOS frameworks are downloaded from `lucra-sdk.s3.amazonaws.com` during `pod install`, and Android SDK artifacts are published to Maven Central.

1. Create a PAT: https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens
2. Select "Classic" with the `read:packages` scope (add `repo` only if you also need private-repository access)
3. Name it something like `Lucra Token`
4. Use it when prompted during install or in CI

## NPM Install

Create a `.npmrc` at the root of your app:

```
//npm.pkg.github.com/:_authToken=[INSERT YOUR GITHUB PERSONAL TOKEN HERE]
@lucra-sports:registry=https://npm.pkg.github.com
```

You can also set it as an environment variable and then use variable replacement. In this example under `GITHUB_PERSONAL_TOKEN`:

```
//npm.pkg.github.com/:_authToken=${GITHUB_PERSONAL_TOKEN}
@lucra-sports:registry=https://npm.pkg.github.com
```

Install the package:

```sh
npm i -S @lucra-sports/lucra-react-native-sdk react-native-haptic-feedback react-native-webview
```

Do not commit `.npmrc` to your repo. Add it to `.gitignore`.

## Expo (Prebuild/Ejected Only)

This SDK does not work with Expo Go. You must use `expo prebuild`, a dev client, or a standalone build.

### Using Expo Build Properties

Install `expo-build-properties` dependency, then update `app.config.js` to set native build properties and register the Lucra plugin:

```javascript
plugins: [
  [
    'expo-build-properties',
    {
      ios: {
        // Apply only if you are using a old expo version
        deploymentTarget: '15.1',
        // Lucra SDK uses third-party services that require network inspection to be kept off.
        networkInspector: false,
      },
      android: {
        minSdkVersion: 24,
        networkInspector: false,
      },
    },
  ],
  '@lucra-sports/lucra-react-native-sdk',
],
```

The plugin forces static frameworks (`ios.useFrameworks = static`). No Podfile hook is needed for Sentry: see [Sentry Framework Linkage](#sentry-framework-linkage).

### Custom Fonts

Follow the `expo-font` guide and ensure Lucra can resolve your font family:

- Android: pass paths relative to `fonts/`.
- iOS: pass the font family name (as shown in Font Book).
- Provide all variations: Regular, Medium, SemiBold, Bold.

### Expo Dev Client

If you use `expo-dev-client`, make sure `networkInspector` is `false`. The SDK uses libraries that block network inspection.

### Venmo Deeplinks (Expo)

Add iOS Info.plist entries for Venmo:

```javascript
infoPlist: {
  CFBundleURLTypes: [
    {
      CFBundleURLSchemes: ['YOUR_APP_BUNDLE_IDENTIFIER.venmo'],
      CFBundleURLName: 'Venmo URL Scheme',
    },
  ],
  LSApplicationQueriesSchemes: ['venmo', 'com.venmo.touch.v2'],
},
```

## iOS Setup

### Deployment Target

If you are using an older React Native/Expo version, you need to set the minimum iOS version to 15.1:

```ruby
platform :ios, 15.1
```

Newer React-Native/Expo versions should already target iOS 16.1, so you might not need this.

### Podfile

Your `ios/Podfile` needs no Lucra source or pod repo. Use static frameworks:

```ruby
use_frameworks! linkage: :static
```

If your Podfile still lists `source 'https://github.com/Lucra-Sports/lucra-ios-sdk.git'`, or your machines and CI ran `pod repo add LucraSDK`, you can remove both: nothing resolves from them any more.

### Lucra iOS SDK Frameworks

The Lucra iOS SDK ships through Swift Package Manager only and is no longer published to CocoaPods. The wrapper keeps you on CocoaPods: during `pod install`, its podspec downloads the frameworks the Swift package uses (`LucraSDK`, `MobileIntelligence` and `GeoComplySDK`) from `https://lucra-sdk.s3.amazonaws.com/ios/spm/<version>/`, checks each one against the SHA-256 checksum published in the Lucra iOS SDK's `Package.swift`, and vendors them in its own pod. Do not also add the `LucraSDK` Swift package to your app; the wrapper already includes the same frameworks.

- `pod install` needs network access to `lucra-sdk.s3.amazonaws.com`, plus `curl` and `unzip`, both of which ship with macOS.
- The frameworks are saved under `node_modules/@lucra-sports/lucra-react-native-sdk/ios-frameworks/<version>/` and later installs reuse them. If a download fails or a checksum doesn't match, `pod install` stops and no partial framework is kept.
- CocoaPods references the frameworks where they are saved and does not copy them into `ios/Pods`. If your CI restores `ios/Pods` from a cache and skips `pod install` on a hit, cache that folder too, or run `pod install` on every build.

### Xcode 27 and CocoaPods Resource Bundles

Xcode 27 refuses to build any target whose deployment target is below iOS 15.0. `react_native_post_install` raises the deployment target on pod targets but not on the resource-bundle targets CocoaPods generates alongside them (`*_Privacy`, `*_resources`), which keep whatever their podspec declared — 9.0 for PromisesObjC, 11.0 for Sentry, 12.x–13.4 for the Firebase, Google and AsyncStorage pods. If your build fails with `The iOS Simulator deployment target 'IPHONEOS_DEPLOYMENT_TARGET' is set to 12.0, but the range of supported deployment target versions is 15.0 to 27.0.x`, add this to your `post_install` hook after `react_native_post_install`:

```ruby
installer.target_installation_results.pod_target_installation_results.each do |_, result|
  result.resource_bundle_targets.each do |bundle_target|
    bundle_target.build_configurations.each do |config|
      config.build_settings['IPHONEOS_DEPLOYMENT_TARGET'] = min_ios_version_supported
    end
  end
end
```

### Sentry Framework Linkage

The Lucra iOS SDK uses `sentry-cocoa` for its own internal diagnostics. It never calls `SentrySDK.start` and sends nothing to your Sentry project.

The native framework does not link Sentry itself. The code that talks to Sentry ships as source inside the wrapper's pod and is compiled into your Pods project against the Sentry your app already resolves, so there is only ever one copy of Sentry in the process. Any `sentry-cocoa` 8.58.0 or newer within 8.x works, and `use_frameworks! linkage: :static` works as is: no `pre_install` hook, no dynamic `Sentry.framework` to embed. The wrapper's podspec declares `Sentry >= 8.58.0, < 9.0`. The cap exists because sentry-cocoa 9.x dropped the `Sentry/HybridSDK` subspec that `@sentry/react-native` 7.x pins, and CocoaPods resolves the root pod and that subspec separately: a range reaching into 9.x installs 9.x sources under an 8.x subspec and `RNSentry` no longer compiles.

If your app also uses Sentry through `@sentry/react-native` 7.x, which pins `Sentry/HybridSDK` to 8.58.0, nothing to align. `@sentry/react-native` 8.x pins sentry-cocoa 9.x and does not resolve against the CocoaPods wrapper yet; a pin below 8.58.0 fails dependency resolution with `could not find compatible versions for pod "Sentry"`.

## Android Setup

### Maven Repository Setup

Lucra Android Native SDK artifacts are published to Maven Central. No additional authentication is required.

Ensure your root `android/build.gradle` includes Maven Central:

```gradle
allprojects {
  repositories {
    google()
    mavenCentral()
  }
}
```

### Sentry Version Alignment (If Your App Uses Sentry)

The Lucra Android SDK depends on `io.sentry:sentry` 8.54.0 for its own internal diagnostics. It never calls `Sentry.init` and sends nothing to your Sentry project. If your app also uses Sentry, every `io.sentry:*` artifact must resolve to the same version, 8.54.0 or newer. Gradle only raises the artifacts both sides share, so `@sentry/react-native` (7.11.0 brings `sentry-android` 8.31.0) leaves `sentry-android-core` at 8.31.0 next to `sentry` 8.54.0, and the app dies at process start, before `Sentry.init`, with `NoClassDefFoundError: io.sentry.util.runtime.IRuntimeManager` in `installContentProviders`; other mixes surface as `Sentry SDK has detected a mix of versions` or `AbstractMethodError`. Pin the group in `android/app/build.gradle` (`sentry-native-ndk` is versioned separately and must be left alone):

```gradle
configurations.all {
  resolutionStrategy.eachDependency { details ->
    if (details.requested.group == 'io.sentry' && details.requested.name != 'sentry-native-ndk') {
      details.useVersion '8.54.0'
    }
  }
}
```

The example app carries this block and runs `@sentry/react-native` 7.11.0 against it.

### Auth0 Compliance (If Your App Does Not Use Auth0)

android {

### Application Requirements

Lucra uses [Coil](https://coil-kt.github.io/coil/) for images and SVGs. Provide the Lucra image loader in your `Application`:

```kotlin
class MyApplication : Application(), ImageLoaderFactory {
  override fun newImageLoader() = LucraCoilImageLoader.get(this)
}
```
