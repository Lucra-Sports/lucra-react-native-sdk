# Reward Sheet

The reward sheet is a bottom sheet that shows the rewards a user has earned and not yet seen: tournament prizes, achievement rewards, and promotion rewards such as a first-deposit bonus. The SDK presents it on its own over your app; no manual invocation is required.

## When it appears

- **Whenever the signed-in user's account changes**: on sign-in, so once on launch, and when the balance, profile or account status changes, which a deposit, a tournament payout or a promotion that pays cash all do. The SDK checks for unseen rewards and presents the sheet over the current screen about a second later. A promotion that does not pay cash does not move the balance, so it appears at the next account change or the next time a Lucra flow opens.
- **When a Lucra flow opens** for a signed-in user. The `MINI_GAME` flow never shows it.

If there are no unseen rewards, or the user is not signed in, nothing is shown. Rewards are marked seen once they are shown, so the sheet does not repeat them. If your app is in the background, the check waits until it returns.

## Presenting it yourself

Some events change no account and open no Lucra flow, such as a game ending in a headless integration, so a reward earned there waits for the next check. To check right away, call:

```ts
await LucraSDK.presentRewardsSheetIfAvailable();
```

It runs the same check as the automatic one and presents the sheet when the user has unseen rewards; it does nothing when they have none, when no user is signed in, or when the sheet is [disabled](#disabling-the-reward-sheet). It is safe to call often: checks run one at a time, and while a reward sheet is already showing the rewards wait for the next check, so the user never gets two sheets. The promise resolves once the check is handed to the native SDK, not when the sheet is shown. It rejects with `notInitialized` when `LucraSDK.init` has not completed.

The example app's "Rewards & Achievements" screen has a "Present Rewards Sheet If Available" button that exercises this call.

## What it shows

- Promotion rewards (such as a deposit bonus or a promotional cash grant), tournament rewards and achievement rewards the user has not seen. Each reward is tagged with how it was earned, and a reward's `disclaimer`, when the backend supplies one, is shown as fine print.
- A tournament or achievement reward that redeems by discount code, claim URL, or both shows "Claim Later" and "Claim Now"; "Claim Now" marks the reward claimed and opens its claim URL when it has one. A promotion shows a single "Continue", which opens its claim URL when it has one.
- With several rewards, "Claim Later" moves on to the next one; the sheet closes after the last one or when the user dismisses it.
- Promotion rewards appear only on this sheet: the headless `LucraSDK.getUserTournamentRewards` and `LucraSDK.getUserAchievements` do not return them. If you turn the sheet off and build your own reward UI, promotions will not appear in it.

## Disabling the Reward Sheet

Pass `allowRewardSheetToDisplay: false` to [`LucraSDK.init`](1.2.0_initialize_client.md) to globally suppress it on both platforms:

```ts
await LucraSDK.init({
  apiKey: 'YOUR_API_KEY',
  environment: LucraSDK.ENVIRONMENT.SANDBOX,
  allowRewardSheetToDisplay: false, // default: true
});
```

When disabled, the SDK never presents the sheet on its own — not on account changes, not when a Lucra flow opens, and not from `LucraSDK.presentRewardsSheetIfAvailable()` — regardless of any other feature flag settings. A tournament's end-of-round sheet still shows what that tournament paid out.

## Android host requirement

On Android, the sheet attaches to the currently resumed activity via AndroidX `FragmentManager`. Only activities that subclass `FragmentActivity` (including `AppCompatActivity`) can host the sheet. React Native's `ReactActivity` extends `AppCompatActivity`, so this is satisfied by default — if your app swaps in a different activity type for its foreground UI, ensure it still subclasses `FragmentActivity`. If no `FragmentActivity` is resumed, the SDK waits for one before fetching, so rewards are not consumed while your app is in the background.
