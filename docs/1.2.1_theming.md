# Theming and Appearance

Lucra UI can be themed through the `theme` object passed to `LucraSDK.init`. Use this to align Lucra screens with your app's colors and typography.

## Theme Properties

All color values are hex strings.

- `primary`, `secondary`, `tertiary`
- `onPrimary`, `onSecondary`, `onTertiary`

`background`, `surface`, `onBackground`, and `onSurface` are owned by Lucra and cannot be overridden.

The theme also takes `light` / `dark` palettes (see [Light and dark mode](#light-and-dark-mode)), an
optional [`themeMode`](#forcing-light-or-dark), and a [`fontFamily`](#fonts).

### Color format

- `#RRGGBB` is the usual form. A leading `#` is optional and `#RGB` shorthand is expanded for you.
- 8-digit hex is **`#AARRGGBB` — alpha first**, not CSS's `#RRGGBBAA`. Passing a CSS-ordered value will render the alpha channel as red.
- Anything else is ignored with a console warning, and that token falls back to the Lucra default.

## Light and dark mode

Supply a `light` and a `dark` palette to have Lucra screens follow the device appearance, re-resolving live as the user switches. Unless you set [`themeMode`](#forcing-light-or-dark), the appearance is derived from *which* palettes you supply:

| Supplied | Appearance |
| --- | --- |
| `light` and `dark` | Follows the device |
| `light` only | Locked to light |
| `dark` only | Locked to dark |
| Flat colors only | Locked to dark |

```ts
const theme = {
  light: {
    primary: '#0B8F3E',
    secondary: '#3F3CB8',
    tertiary: '#5B57E0',
    onPrimary: '#FFFFFF',
    onSecondary: '#FFFFFF',
    onTertiary: '#FFFFFF',
  },
  dark: {
    primary: '#09E35F',
    secondary: '#5E5BD0',
    tertiary: '#9C99FC',
    onPrimary: '#001448',
    onSecondary: '#FFFFFF',
    onTertiary: '#FFFFFF',
  },
};
```

Flat color keys act as a shared base that `light` and `dark` override, so you only repeat the tokens that actually differ:

```ts
const theme = {
  // shared by both appearances
  secondary: '#5E5BD0',
  tertiary: '#9C99FC',
  // differ per appearance
  light: { primary: '#0B8F3E', onPrimary: '#FFFFFF' },
  dark: { primary: '#09E35F', onPrimary: '#001448' },
};
```

## Forcing light or dark

`themeMode` overrides the table above and pins the SDK's appearance regardless of which palettes you
supply:

```ts
const theme = {
  light: { primary: '#0B8F3E', onPrimary: '#FFFFFF' },
  dark: { primary: '#09E35F', onPrimary: '#001448' },
  themeMode: 'light', // 'light' | 'dark' | 'system'
};
```

| `themeMode` | Appearance |
| --- | --- |
| omitted | Derived from the palettes, per the table above |
| `'light'` | Every Lucra screen renders light |
| `'dark'` | Every Lucra screen renders dark |
| `'system'` | Follows the device, switching with it at runtime |

**Omitting it preserves today's behavior exactly**, so this is not a breaking change.

> The Android SDK spells the third option `AUTO`. React Native uses `'system'` — matching iOS and
> `useColorScheme()` — and the bridge maps it. Passing `'auto'` logs a warning naming `'system'`.

### When a forced mode has no matching palette

If you force an appearance you supplied no palette for, **the SDK reuses the palette you did
supply**. `themeMode: 'light'` with only a `dark` palette renders light chrome with dark-tuned brand
colors — which is a real contrast hazard, since an `onPrimary` picked for dark-on-dark now sits
against a light surface.

The wrapper warns in Metro when this happens:

```
[LucraSDK] theme.themeMode is "light" but no "light" palette was supplied, so Lucra reuses your
"dark" palette for it. Check those colors against the light appearance, or supply a "light" palette.
```

The Android SDK logs its own version of this to Logcat. Supplying no palettes at all is fine and
warns about nothing — Lucra's own colors cover both appearances.

Note that flat color keys resolve to the `dark` palette, so flat colors plus `themeMode: 'light'`
is a cross-fill and warns.

`themeMode` is read once, when the SDK initializes.

### Upgrading

Passing flat colors with no `light` or `dark` keeps the SDK locked to dark, which is how every release before light-mode support behaved. Existing integrations need no changes; add a `light` palette when you want Lucra screens to follow the device.

### Android host Activity

When the SDK follows the device appearance — because you supplied both palettes, or set `themeMode: 'system'` — any Activity hosting a Lucra flow must declare `uiMode` in its `configChanges` so it isn't recreated when the appearance changes. React Native's default template already does this:

```xml
<activity
  android:name=".MainActivity"
  android:configChanges="keyboard|keyboardHidden|orientation|screenLayout|screenSize|smallestScreenSize|uiMode">
```

## Fonts

`fontFamily` now uses a single object shape on both iOS and Android. Provide the PostScript family names on iOS and asset paths on Android. All four keys are required:

- `normal`
- `medium`
- `semibold`
- `bold`

Fonts are shared across appearances — there is no per-appearance `fontFamily`.

## Example

```ts
import { Platform } from 'react-native';

const theme = {
  light: {
    primary: '#0B8F3E',
    secondary: '#3F3CB8',
    tertiary: '#5B57E0',
    onPrimary: '#FFFFFF',
    onSecondary: '#FFFFFF',
    onTertiary: '#FFFFFF',
  },
  dark: {
    primary: '#09E35F',
    secondary: '#5E5BD0',
    tertiary: '#9C99FC',
    onPrimary: '#001448',
    onSecondary: '#FFFFFF',
    onTertiary: '#FFFFFF',
  },
  fontFamily: {
    normal:
      Platform.OS === 'ios'
        ? 'Inter Regular'
        : 'fonts/Inter-Regular.ttf',
    medium:
      Platform.OS === 'ios'
        ? 'Inter Medium'
        : 'fonts/Inter-Medium.ttf',
    semibold:
      Platform.OS === 'ios'
        ? 'Inter SemiBold'
        : 'fonts/Inter-SemiBold.ttf',
    bold:
      Platform.OS === 'ios'
        ? 'Inter Bold'
        : 'fonts/Inter-Bold.ttf',
  },
};
```

The types are exported if you want to build palettes separately:

```ts
import type {
  LucraTheme,
  LucraColorSet,
  LucraFontFamily,
} from '@lucra-sports/lucra-react-native-sdk';
```
