# Headless Functionality

Headless functions are API calls that do not display UI. Most require the SDK to be initialized and the user to be logged in.

- Games You Play headless APIs: see [GYP headless functions](2.3_gyp_headless_functions.md)
- Tournament headless APIs: see [Tournament headless functions](3.3_tournaments_headless.md)
- Rewards & Achievements headless APIs: see [Achievements](5.0_achievements.md)
- Mini Games headless APIs: see [Mini Games headless functions](6.1_mini_games_headless.md)

## Error handling

Headless calls surface native errors from the platform bridges:

- Common codes (iOS `LucraSwiftClient.rejectLucraError` / Android `ErrorMapper`): `apiError`, `locationError`, `insufficientFunds`, `notAllowed`, `notInitialized`, `unverified`, `missingDemographicInformation`, `unknown` / `unknownError`.
- Tournament-related calls (Android only): `featureDisabled` — the tournaments feature isn't enabled for your tenant.
- Validation codes thrown before the API call (see `LucraSwiftClient.createRecreationalGame` and `LucraClientModule.createRecreationalGame`): `invalidAtStake`, `invalidRewardType`, `invalidPlayStyle`.
- Configure user / update username specific: `invalid_username`, `not_logged_in`, `unknown_error`, `loading`.
- Phone auth specific (`submitPhoneNumber` / `submitVerificationCode` / `resendCode`): `invalidPhoneNumber`, `phoneNumberNotSubmitted`, `invalidCode`, `alreadyLoggedIn`, `messagingDisabled`, `smsNotDelivered`, `tooManyAttempts`, `networkError`. Typed as `LucraPhoneAuthError`.
- Avatar upload specific: `invalidImage` — the provided uri could not be decoded into an image.
- `unsupported` — the function has no native implementation on the current platform (`getUserKycStatus` on iOS).
- Handshake auth specific (`signInWithHandshakeAuth` / `registerHandshakeAuthTokenProvider`): `noProviderRegistered`, `providerTimedOut`, `providerFailed`, `exchangeFailed`, `tosNotAccepted`, `tenantIdUnavailable`, `profileTimedOut` (Android only). Typed as `LucraHandshakeAuthError`. See [Handshake Authentication](1.2.12_handshake_authentication.md#error-reference).
- `invalidTelemetryLevel` — `logTelemetry` received a level other than `info`, `warning`, or `error`.

Handle them explicitly:

```ts
import { LucraSDK, type LucraSDKError } from '@lucra-sports/lucra-react-native-sdk';

function handleLucraSDKError(e: LucraSDKError) {
  switch (e.code) {
    case 'notInitialized':
      LucraSDK.present({ name: LucraSDK.FLOW.ONBOARDING });
      break;
    case 'unverified':
      LucraSDK.present({ name: LucraSDK.FLOW.VERIFY_IDENTITY });
      break;
    case 'insufficientFunds':
      LucraSDK.present({ name: LucraSDK.FLOW.ADD_FUNDS });
      break;
    case 'missingDemographicInformation':
      LucraSDK.present({ name: LucraSDK.FLOW.DEMOGRAPHIC_COLLECTION });
      break;
    case 'apiError':
    case 'locationError':
      // Retry, show location permission prompt
      break;
    default:
      console.warn('Lucra error', e);
  }
}
```

## User Configuration

### Configure User Properties

**Description:**  
Pushes profile attributes into Lucra for the currently authenticated user. Only non-null values on the supplied `SDKUser` are submitted.

If `configure` is invoked before the Lucra session is established, the request is queued and automatically retried after login. Deprecated properties such as `birthday` are ignored. Any values sent here are also surfaced inside `LucraFlow.VerifyIdentity`, minimizing what the user must re-enter during KYC.

**Phone number implications**

- Provide `phoneNumber` only when you intend to bind the Lucra account to that value. After the number is verified, the SDK login flow requires the same phone for future authentications.
- Skip the field (or pass `null`) if you prefer Lucra to collect and manage the phone number directly.
- Whatever value you send appears pre-filled in the Verify Identity flow.

**User metadata implications**

- Use `metadata` to pass identifiers and traits from your system. This is a Map of Strings to Strings, an `externalId` entry (example: `"externalId" to "clientUserId"`) is recommended at minimum to bind your users to Lucra users. Which will help for score submission and other identifying properties from Lucra systems.

Provide user information so Lucra can create or update the user profile:

```ts
await LucraSDK.configureUser({
  username: 'player123',          // optional
  avatarURL: 'https://...',       // optional
  phoneNumber: '+15555555555',    // optional
  email: 'user@example.com',      // optional
  firstName: 'Mike',              // optional
  lastName: 'Smith',              // optional
  address: {
    address: '123 Main St',       // optional
    addressCont: 'Apt 4B',        // optional
    city: 'New York',             // optional
    state: 'NY',                  // optional
    zip: '10001',                 // optional
  },
  metadata: { "externalId": "..."}, // optional string map to help bind Lucra users to your users
});

const user = await LucraSDK.getUser();
```

### Required/Optional Fields

Field requirements depend on your program configuration. At minimum, pass the fields you have available. The SDK will prompt for missing information when necessary.


## Update Username

Updates only the username of the current user and resolves with the updated user:

```ts
const user = await LucraSDK.updateUsername('newUsername');
```

Parameters:

- `username` (string): The new username.

Returns: `Promise<LucraUser>` — the updated user.

Errors that can be thrown:

- `invalid_username`: The username was rejected, or matches the current username.
- `not_logged_in`: No user is configured.
- `loading` (Android): The user is still loading; retry shortly.
- `unknown_error`: Anything else.

On iOS the SDK has no dedicated username call, so the bridge reconfigures the current user with only the username changed — behavior and validation are otherwise identical.

## Upload User Avatar

Uploads a new avatar image for the current user. The native SDK scales the image, uploads it, and updates the user's `avatarURL`; the [user listener](#user-listener) emits the updated user once the upload completes.

```ts
// e.g. from an image picker result
await LucraSDK.uploadUserAvatar('file:///path/to/image.jpg');
```

Parameters:

- `imageUri` (string): A local `file://` or `content://` (Android) uri, an absolute file path, or a base64 `data:` uri.

Returns: `Promise<void>`

Errors that can be thrown:

- `invalidImage`: The uri could not be decoded into an image.
- `notInitialized`, `notAllowed`, `apiError`, `unknownError`: See [Error handling](#error-handling).

## Get User KYC Status

Resolves `true` when the given user has passed KYC verification:

```ts
const isVerified = await LucraSDK.getUserKycStatus('LUCRA_USER_ID');
```

Parameters:

- `userId` (string): The Lucra user ID to check.

Returns: `Promise<boolean>`

Errors that can be thrown:

- `apiError`: The status check failed (including when the SDK is not initialized).
- `unsupported` (iOS): The iOS Lucra SDK has no headless KYC-status API yet. For the current user, read `accountStatus` from `LucraSDK.getUser()` instead.

## Phone Authentication (headless)

Phone-based passwordless authentication without presenting Lucra's onboarding UI. The flow is:

1. `submitPhoneNumber(phoneNumber)` — validates the number and sends an SMS verification code.
2. `submitVerificationCode(code)` — verifies the code and signs the user in, resolving with the authenticated user.
3. `resendCode()` — re-sends the code to the number from step 1, if needed.

```ts
await LucraSDK.submitPhoneNumber('(555) 123-4567');

// User received the SMS code:
const user = await LucraSDK.submitVerificationCode('123456');
console.log('Logged in as', user.username);

// Or, if the code never arrived:
await LucraSDK.resendCode();
```

Parameters and returns:

- `submitPhoneNumber(phoneNumber: string): Promise<void>` — accepts common US formats (`5551234567`, `+1 555 123 4567`, `(555) 123-4567`); the bridge normalizes the number per platform before handing it to the native SDK.
- `submitVerificationCode(code: string): Promise<LucraUser>` — resolves with the authenticated user. The [user listener](#user-listener) also emits.
- `resendCode(): Promise<void>` — requires a prior successful `submitPhoneNumber` in the same session.

The normalization is done by the exported `formatUsPhoneNumber(input: string, style: 'formatted' | 'digits'): string` helper, which you can also use directly: `'formatted'` returns `(XXX) XXX-XXXX` (what the iOS SDK expects), `'digits'` returns the bare 10-digit string (what the Android SDK expects), and a leading `1`/`+1` US country code is stripped. Input that cannot be reduced to 10 digits is returned unchanged, so the native SDK rejects it with `invalidPhoneNumber` rather than the helper guessing.

Errors that can be thrown (typed as `LucraPhoneAuthError`):

- `notInitialized`: `LucraSDK.init` has not completed.
- `invalidPhoneNumber`: Not a valid US phone number.
- `phoneNumberNotSubmitted`: `submitVerificationCode`/`resendCode` called before `submitPhoneNumber`.
- `invalidCode`: The verification code is empty or incorrect.
- `alreadyLoggedIn`: Log out before starting phone authentication.
- `messagingDisabled`: The user texted STOP to Lucra's verification sender; codes cannot be delivered until they reply START or UNSTOP to that number.
- `smsNotDelivered`: The SMS provider could not deliver the verification text to this number.
- `tooManyAttempts`: Too many send or verify attempts; the user must wait before retrying.
- `networkError`: A network error occurred; the message contains details.
- `unknownError`: Anything else.

## Handshake Authentication (headless)

Signs the user into Lucra from a token your own backend signs — no Lucra login screen — and exposes
the auth state behind it.

```ts
await LucraSDK.registerHandshakeAuthTokenProvider(async () => myBackend.fetchLucraToken());
const user = await LucraSDK.signInWithHandshakeAuth();

const unsubscribe = LucraSDK.subscribeToAuthState(({ isHandshakeAuthInFlight }) => {
  // Show your own spinner while an exchange runs.
});
```

`signInWithHandshakeAuth` rejects with `LucraHandshakeAuthError` codes. Treat `tosNotAccepted`
separately: present `LucraSDK.FLOW.HANDSHAKE_TOS` rather than falling back to phone auth, which
cannot create the account either.

`subscribeToAuthState` also carries `handshakeAuthError` (the **last** failure, cleared when the next
exchange starts) and `isResolvingAuthState` (**iOS only**; `null` on Android). There is a
`useAuthState()` hook and a one-shot `getAuthState()`.

The full integration — the token contract, the ordering constraint, the automatic sign-in paths,
`bypassTosAgreement`, and the error table — is in
[Handshake Authentication](1.2.12_handshake_authentication.md).

## Telemetry Diagnostics

Records a diagnostic through the native Lucra SDK's own telemetry, the same logger fan-out the SDK's code reports through. Use it to confirm the SDK's diagnostics pipeline works in your app. Nothing reaches your own Sentry project: records go to Lucra's SDK Sentry project for the platform, using the DSN compiled into the native SDK.

```ts
await LucraSDK.logTelemetry({
  level: 'info',
  message: 'Checkout screen opened',
  category: 'Checkout',
});

await LucraSDK.logTelemetry({ level: 'error', message: 'Manual test error' });
```

Parameters (single object):

- `level` (`LucraTelemetryLevel`: `'info' | 'warning' | 'error'`): `info` and `warning` record breadcrumbs, stored on the device and attached to the next error event; they never alert. `error` records a non-fatal error event, which creates a Sentry issue and triggers alert emails, so use it sparingly.
- `message` (string): The text to record.
- `category` (string, optional, default `'Lucra'`): iOS tags the record with `lucra.category`; Android has no category field, so the category is prefixed to the message as `[category] message`.

Returns: `Promise<void>`, resolved once the record is handed to the native SDK. Delivery to Sentry is asynchronous and nothing shows in the Sentry UI while the org's error quota is exhausted.

Errors that can be thrown: `notInitialized` when `LucraSDK.init` has not completed, `invalidTelemetryLevel` for an unrecognized level.

The example app's "Telemetry Diagnostics" screen mirrors the iOS SDK Sample's screen of the same name and exercises this call.

## Logout

```ts
await LucraSDK.logout();
```

Ends the Lucra session for the current user.

## User Listener

Subscribe to user updates:

```ts
const unsubscribe = LucraSDK.addListener('user', ({ user, error }) => {
  if (error) {
    console.log('user callback error', error);
    return;
  }

  if (user == null) {
    console.log('User is null (logged out)');
  } else {
    console.log('Received user', user);
  }
});

// Call this when you no longer need the listener (e.g., on unmount).
unsubscribe();
```

## Full Screen Flow Dismissed Listener

```ts
const unsubscribe = LucraSDK.addLucraFlowDismissedListener((flow) => {
  console.log('flow dismissed', flow);
});

// Call this when you no longer need the listener (e.g., on unmount).
unsubscribe();
```
