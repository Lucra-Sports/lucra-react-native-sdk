# Tournament Headless Functions

[Lucra Headless setup](1.2.9_headless_interactions.md)

Use these headless APIs to list, fetch, and join tournaments without showing Lucra UI. Requires `LucraSDK.init` and a configured user.

## Get Recommended Tournaments

```ts
const tournaments = await LucraSDK.getRecomendedTournaments({
  includeClosed: true,
  limit: 50,
  includePrivateViewable: false,
});
```

Example response:

```json
[
  {
    "id": "tournament-1",
    "title": "Weekend Pool",
    "type": "POOL",
    "fee": 5,
    "buyInAmount": 5,
    "description": "Win by placing in the top 10",
    "participants": [
      { "id": "user-1", "username": "alice", "place": 1, "rewardValue": 20 },
      { "id": "user-2", "username": "bob", "place": 2, "rewardValue": 10 }
    ],
    "status": "OPEN",
    "metadata": null,
    "iconUrl": "https://...",
    "expiresAt": "2024-01-01T00:00:00Z",
    "potTotal": 100,
    "isPrivate": false,
    "totalParticipants": 42
  }
]
```

Parameters:
- `includeClosed` (boolean): Include completed tournaments.
- `limit` (number): Max number of tournaments.
- `includePrivateViewable` (boolean, defaults to `false`): Also return private tournaments that are
  *viewable* without a join code. A code is still required to **join** them, so check `isPrivate`
  on each result before offering a one-tap join. On Android this requires Lucra Android SDK 7.0.1
  or newer — see below.

Returns: `Promise<PoolTournament[]>`

Prefer `totalParticipants` over `participants.length` — `participants` is capped by the
leaderboard page size and holds only a subset of entrants on large tournaments.

### Platform differences

`includePrivateViewable`, `isPrivate`, and `totalParticipants` work on both platforms, but on
Android they require **Lucra Android SDK 7.0.1 or newer**. Against an older Android SDK the flag is
ignored and both fields come back `undefined`.

`rewardType` and `payoutStructure` are always absent from `PoolTournament` on **both** platforms.
Only the removed `tournamentMatchup` call populated them; neither the recommended-tournaments
query nor `submitUserScore` returns them. Read a tournament's payout structure from
[Retrieve Tournament Details](#retrieve-tournament-details) (`payoutStructure`).

Errors that can be thrown:

- `apiError` — Network/server failure.
- `locationError` — Geo restriction or location permission issue.
- `insufficientFunds` — User balance too low for entry fees.
- `notAllowed` — User not permitted (suspended/restricted).
- `notInitialized` — SDK/user session not ready.
- `unverified` — Identity verification required.
- `missingDemographicInformation` — Required profile fields missing.
- `unknown` / `unknownError` — Unclassified native SDK failure.

## Retrieve Tournament Details

Fetches a single tournament's details from Lucra's Forge API (`GET /user/tournaments/:id`). The
response mirrors what Forge returns field for field: nothing is derived, reformatted, or filled in
by the native SDKs or the bridge, and the payload is identical on iOS and Android. Every field is
present; a value Forge does not send comes back as `null`. Category fields such as `status`,
`type`, and `timer.state` are plain strings, so handle values you don't recognize — new ones can be
added without an SDK release. Timestamps are ISO 8601 strings. Works without a signed-in user;
when one is signed in, the request is made as that user.

The leaderboard is a separate call, [Retrieve Tournament Leaderboard](#retrieve-tournament-leaderboard).

```ts
const details = await LucraSDK.retrieveTournamentDetails('TOURNAMENT_ID');
```

Parameters:

- `tournamentId` (string): Tournament ID to fetch.

Returns: `Promise<LucraTournamentDetails>`

Fields:

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Tournament ID. |
| `title` / `description` | `string` / `string \| null` | Display copy. |
| `status` | `string` | Simplified lifecycle: `ACTIVE`, `COMPLETED`, or `CANCELED`. |
| `matchupStatus` | `string` | The raw lifecycle status that `status` summarises, such as `OPEN`, `LOCKED`, or `CLOSED`. |
| `type` | `string` | Reward format: `CASH_FIXED`, `CASH_PERCENTAGE`, `TENANT_REWARD`, or `NO_REWARD`. |
| `matchupRewardType` | `string \| null` | Detailed reward type, such as `POOL_TOURNAMENT_CASH_PERCENTAGE_REWARD` or `POOL_TENANT_REWARD`. |
| `visibility` | `string` | `PUBLIC`, `PRIVATE_VIEWABLE`, or `PRIVATE_HIDDEN`. |
| `isPrivate` | `boolean` | `true` for both private visibilities — a join code is required. |
| `isCompleted` / `isNotStarted` / `isExpired` | `boolean` | Lifecycle flags. Read `isCompleted`, not `expiresAt`, to decide whether a tournament is over; some canceled tournaments report `isCompleted: false` even though `status` is `CANCELED`. |
| `isJoinable` | `boolean` | Whether someone who has not joined could join now. It does not reflect the current user. |
| `gameId` | `string \| null` | The game the tournament is played on. |
| `game` | `LucraTournamentDetailsGame \| null` | `gameId`, `minigameEnabled`, `scoringUnit`, `imageBgUrl`, `iconUrl`; `null` when there is no game. |
| `imageUrl` | `string \| null` | The tournament's own image, when it has one. |
| `displayImageUrl` | `string \| null` | The image to show: the tournament image, else the game's background, else the game's icon. |
| `buyIn` | `string` | Entry fee as a two-decimal string, such as `"5.00"`. |
| `buyInAmount` | `number` | Entry fee in dollars. |
| `freeBuyIn` | `boolean` | `true` when the entry fee is zero. |
| `feePercent` | `string` | Fee percentage as a two-decimal string. |
| `poolNetAmount` | `number` | Prize pool after fees, in dollars. `0` when there is no cash pool. |
| `poolNetAmountComplete` | `number` | Prize pool after fees if the tournament fills. |
| `participantsCount` | `number` | Current number of entrants. |
| `maxParticipants` | `number \| null` | Participant cap; `null` when uncapped. |
| `maxAttempts` | `number \| null` | Attempts allowed per user; `null` when unlimited. |
| `startsAt` / `expiresAt` | `string \| null` | When the tournament begins and when it stops accepting entries. Scores can still be submitted after `expiresAt`. |
| `signUpStart` / `signUpEnd` / `createdAt` | `string \| null` | Sign-up window and creation time. |
| `timer` | `LucraTournamentDetailsTimer` | `state` (`before_signup`, `signup_open`, `before`, `ongoing`, or `ended`), an English `caption` such as `"Ends in 2 hours"`, and `targetAt`, the time the caption counts to. The caption can be a minute stale; render a live countdown from `targetAt`. |
| `howToPlay` | `LucraTournamentDetailsHowToPlayStep[] \| null` | Ordered steps (`step`, `text`); `null` when the tournament and its game define none. |
| `terms` | `LucraTournamentDetailsTerm[]` | Terms the user confirms before joining (`title`, `description`). |
| `payoutStructure` | `LucraTournamentDetailsPayoutStructure` | Always present; see below. |
| `leaderboardColumns` | `LucraTournamentDetailsLeaderboardColumn[]` | The columns to render for the leaderboard (`name`, `label`). The payout column is present only while payouts are visible. |
| `notices` | `LucraTournamentDetailsNotice[]` | Explanations for hidden or altered values: `type` (such as `PAYOUT_HIDDEN_BELOW_THRESHOLD`), `message`, and `affectedFields`, the paths of the fields it explains (such as `payoutStructure.jackpotAmount`). |

`payoutStructure` has `title`, `description`, `labelTitle`, `labelDescription`, `noPayout`,
`isPercentagePayout`, `showAmount` (percentage pools hide dollar amounts until the pool reaches
$25), `jackpotDescriptor`, `jackpotAmount` (formatted; `null` while payouts are hidden or when the
tournament pays no cash), and `rewards`. Each reward has `place` and `endPlace` (equal for a single
position), `placeLabel`, `positionLabel`, `value` (dollar amount; `null` for tenant-reward
tournaments and while payouts are hidden), `rewardLabel` (the percentage label on percentage
payouts), `amountLabel`, and `catalogReward` — the prize on tenant-reward tournaments, `null`
otherwise. A `catalogReward` has `id`, `type`, `title`, `descriptor`, `iconUrl`, `bannerIconUrl`,
`disclaimer`, and `config`, the reward's tenant-authored configuration object (empty when there is
none). Redemption details are withheld because the reward has not been earned yet; use
`getUserTournamentRewards` for earned rewards.

Errors that can be thrown:

- `apiError` — The Forge request failed; the message is the server's.
- `notInitialized` — iOS, before `LucraSDK.init` has completed. Android reports the same condition as `apiError` with an initialization message.
- `locationError` — Android only, when the SDK's geo-compliance check fails.
- `unknownError` — Unclassified native SDK failure.

## Retrieve Tournament Leaderboard

Fetches one page of a tournament's leaderboard from Forge (`GET /user/tournaments/:id/leaderboard`)
and, when a user is signed in, that user's own entry from `GET /user/tournaments/:id/leaderboard/me`
— so `currentUserEntry` carries their standing even when it falls outside the requested page. Both
responses are mirrored field for field. If either request fails, the whole call rejects. Works
without a signed-in user, in which case `currentUserEntry` is `null` and `isCurrentUser` is `false`
on every row.

```ts
const leaderboard = await LucraSDK.retrieveTournamentLeaderboard('TOURNAMENT_ID', {
  limit: 25,
  offset: 0,
});
```

Parameters:

- `tournamentId` (string): Tournament ID to fetch.
- `options` (object, optional):
  - `limit` (number, optional, default `10`): Number of entries to return. Lucra accepts up to `100`.
  - `offset` (number, optional, default `0`): Number of entries to skip.

Returns: `Promise<LucraTournamentLeaderboard>`

Example response:

```json
{
  "entries": [
    {
      "userId": "user-1",
      "userName": "alice",
      "userMetadata": null,
      "userAvatarUrl": "https://...",
      "position": 1,
      "positionOverride": null,
      "score": 1500,
      "lastUpdatedAt": "2026-02-24T12:00:00.000Z",
      "rank": 1,
      "name": "alice",
      "points": "1,500",
      "payout": "$94.50",
      "isCurrentUser": false,
      "rewardTotalAmount": 105,
      "rewardNetAmount": 94.5,
      "rewardFeeAmount": 10.5,
      "rewardNetAmountComplete": 225,
      "numberOfParticipants": 42,
      "bestAttempt": 2,
      "openAttempt": null,
      "lastAttempt": 2,
      "canSubmitNewScore": false
    }
  ],
  "totalCount": 42,
  "currentUserEntry": {
    "userId": "user-9",
    "userName": "you",
    "userMetadata": null,
    "userAvatarUrl": null,
    "position": 7,
    "positionOverride": null,
    "score": 1200,
    "lastUpdatedAt": "2026-02-24T12:00:00.000Z"
  }
}
```

Fields:

| Field | Type | Description |
|---|---|---|
| `entries` | `LucraTournamentLeaderboardEntry[]` | The requested page of ranked participants. |
| `totalCount` | `number \| null` | Number of entries across all pages. `null` when Forge did not report one; then fall back to comparing the page size against `entries.length`. |
| `currentUserEntry` | `LucraTournamentLeaderboardCurrentUserEntry \| null` | The signed-in user's own standing, wherever it falls. `null` when no user is signed in or the user has no standing yet. |

Each entry:

| Field | Type | Description |
|---|---|---|
| `userId` | `string` | Lucra user ID. |
| `userName` / `userAvatarUrl` | `string \| null` | Username and avatar. |
| `userMetadata` | `Record<string, unknown> \| null` | The user's tenant metadata; `null` when there is none. |
| `name` | `string` | Display name: the username or `"Unknown"`, suffixed with `" (You)"` on the signed-in user's own row. |
| `rank` | `number \| null` | Display rank, with ties sharing a rank; `null` until the user has a score. |
| `position` / `positionOverride` | `number` / `number \| null` | Sequential position (1, 2, 3, …) and the tie-aware position (1, 2, 2, 4, …); `positionOverride` is `null` when it equals `position`. |
| `score` / `points` | `number \| null` / `string \| null` | Best score and its display string; `null` until the user has a score. |
| `payout` | `string \| null` | Formatted reward, such as `"$21.50"`; `null` when payouts are hidden, the row has no score, or the reward is zero. |
| `isCurrentUser` | `boolean` | `true` on the signed-in user's own row; always `false` signed out. |
| `rewardTotalAmount` / `rewardNetAmount` / `rewardFeeAmount` / `rewardNetAmountComplete` | `number` | The row's reward before fees, after fees, the fee itself, and after fees if the tournament fills, in dollars. |
| `numberOfParticipants` | `number` | Entrant count. |
| `bestAttempt` / `openAttempt` / `lastAttempt` | `number \| null` | Attempt numbers of the row's best score, open attempt, and latest attempt. |
| `canSubmitNewScore` | `boolean` | Whether the row's user has an open attempt. |
| `lastUpdatedAt` | `string \| null` | When the leaderboard was last recomputed. |

`currentUserEntry` has `userId`, `userName`, `userMetadata`, `userAvatarUrl`, `position`,
`positionOverride`, `score`, and `lastUpdatedAt`, as on an entry.

### Paging the leaderboard

```ts
const pageSize = 50;
let offset = 0;
const entries: LucraTournamentLeaderboardEntry[] = [];

while (true) {
  const page = await LucraSDK.retrieveTournamentLeaderboard('TOURNAMENT_ID', {
    limit: pageSize,
    offset,
  });
  entries.push(...page.entries);
  if (page.totalCount !== null && entries.length >= page.totalCount) break;
  if (page.entries.length < pageSize) break;
  offset += pageSize;
}
```

Errors that can be thrown: the same codes as [Retrieve Tournament Details](#retrieve-tournament-details).

### Migrating from the earlier `getTournamentDetails`

The earlier `TournamentDetails` payload (backed by `ui_tournament_details`) was a single combined
response. It is replaced by `retrieveTournamentDetails`, named after the native SDK method and
returning `LucraTournamentDetails`, plus `retrieveTournamentLeaderboard`; the `tournamentMatchup` call
is gone:

| Earlier | Now |
|---|---|
| `tournamentMatchup(id)` | Removed. `retrieveTournamentDetails(id)` for the tournament, `retrieveTournamentLeaderboard(id)` for its standings. |
| `getTournamentDetails(id, { leaderboardLimit, leaderboardOffset })` | `retrieveTournamentDetails(id)` and `retrieveTournamentLeaderboard(id, { limit, offset })` — the call is renamed to match the native `retrieveTournamentDetails` |
| `leaderboard.rows`, `leaderboard.pagination.totalCount` | `LucraTournamentLeaderboard.entries`, `.totalCount` |
| `leaderboard.columns` | `LucraTournamentDetails.leaderboardColumns` |
| `userLeaderboardRow` | `LucraTournamentLeaderboard.currentUserEntry`, or the entry whose `isCurrentUser` is `true` |
| `visibilityLevel` (Android only) | `visibility` (both platforms) |
| `status` (Android only) | `status` (both platforms); `matchupStatus` is the raw lifecycle status |
| `totalParticipants` | `participantsCount` |
| `rewardType` | `matchupRewardType` |
| `minigameEnabled` | `game.minigameEnabled` |
| `timer.state` (`NOT_STARTED` \| `STARTED` \| `ENDED`) | `timer.state` (`before_signup` \| `signup_open` \| `before` \| `ongoing` \| `ended`), plus `targetAt` |
| `payoutStructure` optional | `payoutStructure` always present |
| `payoutStructure.rewards[].catalogReward.description` | `catalogReward.descriptor`, plus `config` |
| `howToPlay` as `[]` when empty | `null` when there are no steps |
| Optional fields absent | Every field present, `null` when Forge sends none |
| `attemptData`, `earnedRewards`, `remainingAttemptsText` | Not available from these calls; `getUserTournamentRewards` returns earned rewards |

## Join Tournament

```ts
await LucraSDK.joinTournament('TOURNAMENT_ID');
```

Parameters:
- `tournamentId` (string): Tournament ID to join.

Returns: `Promise<void>`

### Error handling example

```ts
import { LucraSDK, type LucraSDKError } from '@lucra-sports/lucra-react-native-sdk';

try {
  await LucraSDK.joinTournament('TOURNAMENT_ID');
} catch (error) {
  const e = error as LucraSDKError;
  switch (e.code) {
    case 'notInitialized':
      // Ensure SDK init + user config
      break;
    case 'unverified':
      await LucraSDK.present({ name: LucraSDK.FLOW.VERIFY_IDENTITY });
      break;
    case 'insufficientFunds':
      await LucraSDK.present({ name: LucraSDK.FLOW.ADD_FUNDS });
      break;
    case 'missingDemographicInformation':
      await LucraSDK.present({ name: LucraSDK.FLOW.DEMOGRAPHIC_COLLECTION });
      break;
    case 'notAllowed':
      // Show restriction message or support contact
      break;
    case 'locationError':
      // Prompt user to enable location / check state eligibility
      break;
    case 'apiError':
      // Retry or show generic failure
      break;
    default:
      console.warn('Unknown tournament error', e);
  }
}
```

## Submit User Score

Submits the current user's score for a tournament — for tenants that report scores manually instead of through Lucra's automatic tracking.

```ts
const updated = await LucraSDK.submitUserScore({
  tournamentId: 'TOURNAMENT_ID',
  score: 1200,
  isFinal: false,
  metadata: { level: '3' },
});
```

Parameters (single object):

- `tournamentId` (string): Tournament ID to submit the score to.
- `score` (number): The score for the given attempt. Fractional scores are accepted on both platforms.
- `isFinal` (boolean): Whether this is the user's final attempt.
- `metadata` (`Record<string, string>`, optional, default `{}`): Metadata to include with the payload.

Returns: `Promise<PoolTournament | null>` — the updated tournament (see [Types](#types)), or `null` when the native SDK returns none (iOS).

Errors that can be thrown: the same codes as [Join Tournament](#join-tournament) (`notInitialized`, `unverified`, `insufficientFunds`, `missingDemographicInformation`, `notAllowed`, `locationError`, `apiError`, `unknownError`), plus Android-only `featureDisabled` and iOS-only `invalidScore` (a non-finite score; JS validation throws before reaching the bridge, so this iOS code is a backstop). The call requests device location before submitting, so it can fail with `locationError` when location permission is missing.

## Auto-Join Tournaments

Automatically or manually join all eligible free-entry tournaments for the current user.

By default (`autoJoin: true` at [init](1.2.0_initialize_client.md#required-configuration)), the SDK joins eligible tournaments as soon as the user authenticates. Set `autoJoin: false` at init to suppress automatic joining and trigger it manually instead — for example after a location permission is granted:

```ts
const joinedIds = await LucraSDK.autoJoinTournaments();
// joinedIds: string[] — IDs of tournaments joined in this call
```

Returns: `Promise<string[]>` — IDs of tournaments joined in this call.

The call respects the same prerequisites as automatic joining (location permission granted, user verified, feature enabled). It rejects with a structured error code if any prerequisite isn't met — `featureDisabled` when auto-join is not enabled for your integration, on both platforms.

The `onAutoJoinedTournaments` contest-listener event fires alongside the promise, so existing listeners continue to work regardless of whether joining was triggered automatically or manually:

```ts
const unsubscribe = LucraSDK.addContestListener({
  onAutoJoinedTournaments: (tournamentIds: string[]) => {
    console.log('Auto-joined tournaments:', tournamentIds);
  },
});

// Call this when you no longer need the listener (e.g., on unmount).
unsubscribe();
```

## Types

```ts
type PoolTournament = {
  id: string;
  title: string;
  type: string;
  fee: number;
  buyInAmount: number;
  description?: string;
  participants: PoolTournamentParticipant[];
  status: string;
  metadata?: string;
  iconUrl?: string;
  expiresAt?: string;
  potTotal: number;
  // Never populated: only the removed tournamentMatchup filled these
  rewardType?: string;
  payoutStructure?: PayoutStructure;
  isPrivate?: boolean;
  totalParticipants?: number;
};

type PoolTournamentParticipant = {
  id: string;
  username: string;
  place?: number;
  rewardValue?: number;
};

type PayoutStructure = {
  title: string;
  description: string;
  labelTitle?: string;
  labelDescription?: string;
  noPayout: boolean;
  isPercentagePayout: boolean;
  showAmount: boolean;
  jackpotAmount?: string;
  jackpotDescriptor?: string;
  rewards: PayoutReward[];
};

type PayoutReward = {
  place?: number;
  endPlace?: number; // for tie ranges; equals place for a single position
  placeLabel?: string; // e.g. "1st", "4th–10th"
  positionLabel?: string; // e.g. "1st Place"
  rewardLabel?: string; // e.g. "40%" or "Grand Prize"
  amountLabel?: string; // e.g. "$1,000"
  value?: number;
  catalogReward?: CatalogReward; // present only on tangible-prize rows
};

// Tangible reward item. Intentionally excludes redemption details
// (discount codes, claim URLs, free-item IDs).
type CatalogReward = {
  id: string;
  type: string;
  title: string;
  description?: string;
  iconUrl?: string;
  bannerIconUrl?: string;
  disclaimer?: string;
};
```

The [Retrieve Tournament Details](#retrieve-tournament-details) response is typed by the exported `LucraTournamentDetails` type and its nested types (`LucraTournamentDetailsTimer`, `LucraTournamentDetailsHowToPlayStep`, `LucraTournamentDetailsTerm`, `LucraTournamentDetailsPayoutStructure`, `LucraTournamentDetailsPayoutReward`, `LucraTournamentDetailsCatalogReward`, `LucraTournamentDetailsLeaderboardColumn`, `LucraTournamentDetailsNotice`, `LucraTournamentDetailsGame`). The [Retrieve Tournament Leaderboard](#retrieve-tournament-leaderboard) response is typed by `LucraTournamentLeaderboard` (`LucraTournamentLeaderboardEntry`, `LucraTournamentLeaderboardCurrentUserEntry`).

## Usage examples

### Join with demographic prompt fallback

```ts
try {
  await LucraSDK.joinTournament('<tournament-id>');
} catch (e: any) {
  if (e.code === 'missingDemographicInformation') {
    LucraSDK.present({ name: LucraSDK.FLOW.DEMOGRAPHIC_COLLECTION });
  } else {
    throw e;
  }
}
```

### Launch demographic form directly

```ts
LucraSDK.present({ name: LucraSDK.FLOW.DEMOGRAPHIC_COLLECTION });
```

### Check user demographics before calling join

```ts
const user = await LucraSDK.getUser();
const isMissingDemo = !user.email || !user.address?.zip;
if (isMissingDemo) {
  LucraSDK.present({ name: LucraSDK.FLOW.DEMOGRAPHIC_COLLECTION });
}
```
