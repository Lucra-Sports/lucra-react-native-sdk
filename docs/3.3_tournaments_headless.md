# Tournament Headless Functions

[Lucra Headless setup](1.2.9_headless_interactions.md)

Use these headless APIs to list, fetch, and join tournaments without showing Lucra UI. Requires `LucraSDK.init` and a configured user.

## Get Recommended Tournaments

```ts
const tournaments = await LucraSDK.getRecomendedTournaments({
  includeClosed: true,
  limit: 50,
  includePrivateViewable: false,
});
```

Example response:

```json
[
  {
    "id": "tournament-1",
    "title": "Weekend Pool",
    "type": "POOL",
    "fee": 5,
    "buyInAmount": 5,
    "description": "Win by placing in the top 10",
    "participants": [
      { "id": "user-1", "username": "alice", "place": 1, "rewardValue": 20 },
      { "id": "user-2", "username": "bob", "place": 2, "rewardValue": 10 }
    ],
    "status": "OPEN",
    "metadata": null,
    "iconUrl": "https://...",
    "expiresAt": "2024-01-01T00:00:00Z",
    "potTotal": 100,
    "isPrivate": false,
    "totalParticipants": 42
  }
]
```

Parameters:
- `includeClosed` (boolean): Include completed tournaments.
- `limit` (number): Max number of tournaments.
- `includePrivateViewable` (boolean, defaults to `false`): Also return private tournaments that are
  *viewable* without a join code. A code is still required to **join** them, so check `isPrivate`
  on each result before offering a one-tap join. On Android this requires Lucra Android SDK 7.0.1
  or newer — see below.

Returns: `Promise<PoolTournament[]>`

Prefer `totalParticipants` over `participants.length` — `participants` is capped by the
leaderboard page size and holds only a subset of entrants on large tournaments.

### Platform differences

`includePrivateViewable`, `isPrivate`, and `totalParticipants` work on both platforms, but on
Android they require **Lucra Android SDK 7.0.1 or newer**. Against an older Android SDK the flag is
ignored and both fields come back `undefined`.

`rewardType` and `payoutStructure` are always absent from recommended-list results on **both**
platforms. Neither native recommended-tournaments query returns them; fetch
[Get Tournament Details](#get-tournament-details) for a specific tournament to read its reward
structure.

Leaderboard paging defaults differ. When `leaderboardLimit` is omitted from
[Get Tournament Details](#get-tournament-details), iOS requests 10 rows, while Android passes
`null` and takes whatever page size the API chooses. Pass `leaderboardLimit` explicitly if you
need the same page size on both platforms, and read `leaderboard.pagination.totalCount` rather
than assuming one.

Errors that can be thrown:

- `apiError` — Network/server failure.
- `locationError` — Geo restriction or location permission issue.
- `insufficientFunds` — User balance too low for entry fees.
- `notAllowed` — User not permitted (suspended/restricted).
- `notInitialized` — SDK/user session not ready.
- `unverified` — Identity verification required.
- `missingDemographicInformation` — Required profile fields missing.
- `unknown` / `unknownError` — Unclassified native SDK failure.

## Get Tournament Matchup

> For headless tournament UIs, prefer [Get Tournament Details](#get-tournament-details) — a smaller response backed by the same API that powers Lucra's in-app tournament details screen. The native SDKs deprecate the heavier call behind `tournamentMatchup`.

```ts
const tournament = await LucraSDK.tournamentMatchup('TOURNAMENT_ID');
```

Parameters:
- `tournamentId` (string): Tournament ID to fetch.

Returns: `Promise<PoolTournament>`

As of native SDK **iOS 5.5.0 / Android 6.6.0**, this call also returns the full tournament reward structure — additively, alongside the existing fields:

- `rewardType` — raw API reward category (`"POOL_CASH_REWARD"` for cash tournaments, `"POOL_TENANT_REWARD"` for tangible-prize tournaments). Use it to choose how to present rewards.
- `payoutStructure` — the complete payout structure backing Lucra's own tournament details screens: pre-formatted place/position/reward/amount labels, jackpot total, percentage-vs-fixed and show-amount flags, and an ordered list of reward rows. Each row may carry a `catalogReward` (tangible prize) for reward-based tournaments.

Both are optional — `rewardType` is omitted and `payoutStructure` is absent when the backend returns none. `catalogReward` deliberately never includes redemption details (discount codes, claim URLs, free-item IDs); use `getUserTournamentRewards` for a claimed reward's redemption payload. Tournament details can be fetched without an authenticated user.

Errors that can be thrown:

- `apiError`
- `locationError`
- `insufficientFunds`
- `notAllowed`
- `notInitialized`
- `unverified`
- `missingDemographicInformation`
- `unknown` / `unknownError`

Example response:

## Get Tournament Details

Fetches the lightweight tournament details backed by the `ui_tournament_details` API — the same response that powers Lucra's in-app tournament details screen. This is the recommended headless call for rendering a tournament screen yourself: it includes the leaderboard, payout structure, attempt data, how-to-play steps, terms, and pre-formatted labels, without the heavier participant payload of `tournamentMatchup`. Works without an authenticated user (user-specific sections like `userLeaderboardRow` and `attemptData` are simply absent).

```ts
const details = await LucraSDK.getTournamentDetails('TOURNAMENT_ID', {
  leaderboardLimit: 25,
  leaderboardOffset: 0,
});
```

Parameters:

- `tournamentId` (string): Tournament ID to fetch.
- `options` (object, optional):
  - `leaderboardLimit` (number, optional): Page size for the leaderboard section.
  - `leaderboardOffset` (number, optional): Page offset for the leaderboard section.
  - Omit both to receive the native SDK's default first page; read `leaderboard.pagination.totalCount` for the total number of rows.

Returns: `Promise<TournamentDetails>`

Example response:

```json
{
  "id": "tournament-1",
  "title": "Weekend Pool",
  "description": "Win by placing in the top 10",
  "imageUrl": "https://...",
  "isPrivate": false,
  "isCompleted": false,
  "isNotStarted": false,
  "isExpired": false,
  "freeBuyIn": true,
  "buyInAmount": 0,
  "status": "OPEN",
  "visibilityLevel": "PUBLIC",
  "maxParticipants": 100,
  "totalParticipants": 42,
  "rewardType": "POOL_CASH_REWARD",
  "gameId": "game-1",
  "minigameEnabled": true,
  "howToPlay": [{ "step": 1, "text": "Play the game to post a score" }],
  "earnedRewards": [],
  "timer": { "caption": "Ends in 2h 15m", "state": "STARTED" },
  "attemptData": {
    "canJoinTournament": false,
    "isReplayable": true,
    "isUserPresent": true,
    "attemptsRemaining": 2,
    "rankVariation": 1,
    "scores": [{ "attempt": 1, "score": "1200", "isBest": true }]
  },
  "payoutStructure": {
    "title": "Payouts",
    "description": "Top finishers win",
    "noPayout": false,
    "isPercentagePayout": true,
    "showAmount": true,
    "rewards": [
      { "place": 1, "placeLabel": "1st", "rewardLabel": "50%", "amountLabel": "$50", "value": 50 }

    "columns": [{ "name": "rank", "label": "Rank" }],

      { "userId": "user-1", "name": "alice", "rank": 1, "points": "1500", "payout": "$50" }
```

Platform notes:

- `status` and `visibilityLevel` (`PUBLIC` | `PRIVATE_VIEWABLE` | `PRIVATE_HIDDEN`) are Android-only.
- `expiresAt` / `startsAt` are ISO 8601 timestamps on both platforms.
- `attemptData.remainingAttemptsText` is iOS-only.
- `timer.state` is normalized to `NOT_STARTED` | `STARTED` | `ENDED` on both platforms.
- `earnedRewards[].reward` and `payoutStructure.rewards[].catalogReward` use the same `CatalogReward` shape as `tournamentMatchup`, and intentionally exclude redemption details — use `getUserTournamentRewards` for a claimed reward's redemption payload.

Errors that can be thrown: the same codes as [Get Tournament Matchup](#get-tournament-matchup), plus Android-only `featureDisabled`.

## Join Tournament

```ts
await LucraSDK.joinTournament('TOURNAMENT_ID');
```

Parameters:
- `tournamentId` (string): Tournament ID to join.

Returns: `Promise<void>`

### Error handling example

```ts
import { LucraSDK, type LucraSDKError } from '@lucra-sports/lucra-react-native-sdk';

try {
  await LucraSDK.joinTournament('TOURNAMENT_ID');
} catch (error) {
  const e = error as LucraSDKError;
  switch (e.code) {
    case 'notInitialized':
      // Ensure SDK init + user config
      break;
    case 'unverified':
      await LucraSDK.present({ name: LucraSDK.FLOW.VERIFY_IDENTITY });
      break;
    case 'insufficientFunds':
      await LucraSDK.present({ name: LucraSDK.FLOW.ADD_FUNDS });
      break;
    case 'missingDemographicInformation':
      await LucraSDK.present({ name: LucraSDK.FLOW.DEMOGRAPHIC_COLLECTION });
      break;
    case 'notAllowed':
      // Show restriction message or support contact
      break;
    case 'locationError':
      // Prompt user to enable location / check state eligibility
      break;
    case 'apiError':
      // Retry or show generic failure
      break;
    default:
      console.warn('Unknown tournament error', e);
  }
}
```

## Submit User Score

Submits the current user's score for a tournament — for tenants that report scores manually instead of through Lucra's automatic tracking.

```ts
const updated = await LucraSDK.submitUserScore({
  tournamentId: 'TOURNAMENT_ID',
  score: 1200,
  isFinal: false,
  metadata: { level: '3' },
});
```

Parameters (single object):

- `tournamentId` (string): Tournament ID to submit the score to.
- `score` (number): The score for the given attempt. Fractional scores are accepted on both platforms.
- `isFinal` (boolean): Whether this is the user's final attempt.
- `metadata` (`Record<string, string>`, optional, default `{}`): Metadata to include with the payload.

Returns: `Promise<PoolTournament | null>` — the updated tournament (see [Types](#types)), or `null` when the native SDK returns none (iOS).

Errors that can be thrown: the same codes as [Join Tournament](#join-tournament) (`notInitialized`, `unverified`, `insufficientFunds`, `missingDemographicInformation`, `notAllowed`, `locationError`, `apiError`, `unknownError`), plus Android-only `featureDisabled` and iOS-only `invalidScore` (a non-finite score; JS validation throws before reaching the bridge, so this iOS code is a backstop). The call requests device location before submitting, so it can fail with `locationError` when location permission is missing.

## Auto-Join Tournaments

Automatically or manually join all eligible free-entry tournaments for the current user.

By default (`autoJoin: true` at [init](1.2.0_initialize_client.md#required-configuration)), the SDK joins eligible tournaments as soon as the user authenticates. Set `autoJoin: false` at init to suppress automatic joining and trigger it manually instead — for example after a location permission is granted:

```ts
const joinedIds = await LucraSDK.autoJoinTournaments();
// joinedIds: string[] — IDs of tournaments joined in this call
```

Returns: `Promise<string[]>` — IDs of tournaments joined in this call.

The call respects the same prerequisites as automatic joining (location permission granted, user verified, feature enabled). It rejects with a structured error code if any prerequisite isn't met.

The `onAutoJoinedTournaments` contest-listener event fires alongside the promise, so existing listeners continue to work regardless of whether joining was triggered automatically or manually:

```ts
const unsubscribe = LucraSDK.addContestListener({
  onAutoJoinedTournaments: (tournamentIds: string[]) => {
    console.log('Auto-joined tournaments:', tournamentIds);
  },
});

// Call this when you no longer need the listener (e.g., on unmount).
unsubscribe();
```

## Types

```ts
type PoolTournament = {
  id: string;
  title: string;
  type: string;
  fee: number;
  buyInAmount: number;
  description?: string;
  participants: PoolTournamentParticipant[];
  status: string;
  metadata?: string;
  iconUrl?: string;
  expiresAt?: string;
  potTotal: number;
  // Reward structure (native iOS 5.5.0 / Android 6.6.0+)
  rewardType?: string;
  payoutStructure?: PayoutStructure;
  isPrivate?: boolean;
  totalParticipants?: number;
};

type PoolTournamentParticipant = {
  id: string;
  username: string;
  place?: number;
  rewardValue?: number;
};

type PayoutStructure = {
  title: string;
  description: string;
  labelTitle?: string;
  labelDescription?: string;
  noPayout: boolean;
  isPercentagePayout: boolean;
  showAmount: boolean;
  jackpotAmount?: string;
  jackpotDescriptor?: string;
  rewards: PayoutReward[];
};

type PayoutReward = {
  place?: number;
  endPlace?: number; // for tie ranges; equals place for a single position
  placeLabel?: string; // e.g. "1st", "4th–10th"
  positionLabel?: string; // e.g. "1st Place"
  rewardLabel?: string; // e.g. "40%" or "Grand Prize"
  amountLabel?: string; // e.g. "$1,000"
  value?: number;
  catalogReward?: CatalogReward; // present only on tangible-prize rows
};

// Tangible reward item. Intentionally excludes redemption details
// (discount codes, claim URLs, free-item IDs).
type CatalogReward = {
  id: string;
  type: string;
  title: string;
  description?: string;
  iconUrl?: string;
  bannerIconUrl?: string;
  disclaimer?: string;
};
```

The [Get Tournament Details](#get-tournament-details) response is typed by the exported `TournamentDetails` type, along with its section types (`TournamentDetailsLeaderboard`, `TournamentDetailsLeaderboardColumn`, `TournamentDetailsLeaderboardRow`, `TournamentDetailsAttemptData`, `TournamentDetailsAttemptScore`, `TournamentDetailsTimer`, `TournamentDetailsEarnedReward`, `TournamentDetailsHowToPlayStep`, `TournamentDetailsTerm`).

## Event: Tournament Joined

```ts
const unsubscribe = LucraSDK.addContestListener({
  onTournamentJoined: (tournamentId: string, gameId?: string) => {
    console.log(`User joined tournament: ${tournamentId}`, gameId);
  },
});

// Call this when you no longer need the listener (e.g., on unmount).
unsubscribe();
```

## Usage examples

### Join with demographic prompt fallback

```ts
try {
  await LucraSDK.joinTournament('<tournament-id>');
} catch (e: any) {
  if (e.code === 'missingDemographicInformation') {
    LucraSDK.present({ name: LucraSDK.FLOW.DEMOGRAPHIC_COLLECTION });
  } else {
    throw e;
  }
}
```

### Launch demographic form directly

```ts
LucraSDK.present({ name: LucraSDK.FLOW.DEMOGRAPHIC_COLLECTION });
```

### Check user demographics before calling join

```ts
const user = await LucraSDK.getUser();
const isMissingDemo = !user.email || !user.address?.zip;
if (isMissingDemo) {
  LucraSDK.present({ name: LucraSDK.FLOW.DEMOGRAPHIC_COLLECTION });
}
```
